# Архитектурная диаграмма

## Общая схема системы

```
[User]
   ↓
[Frontend (Web)]
   ↓
[Backend API (REST)]
   ↓
[PostgreSQL Database]
```

---

## Расширенная архитектура

```
[User]
   ↓
[Frontend]
   ↓
[Backend (REST API)]
   ├── Auth Service
   ├── User/Profile Service
   ├── Collections Service
   ├── Items Service
   ├── Photos Service
   ├── Favorites Service
   ├── Notifications Service
   ├── Analytics Service
   ↓
[PostgreSQL Database]
```

---

## Описание компонентов
### User

Пользователь приложения, непосредственно взаимодействующий с ним.

* создаёт аккаунт
* заводит свою коллекцию (или несколько)
* добавляет туда предметы с подробным их описанием
* смотрит коллекции и предметы других пользователей, понравившиеся добавляет в отдельный список
* модератор следит за соблюдением правил и, при необходимости, блокирует нарушителей

---

### Frontend (Web)

Клиентская часть приложения, с которой взаимодействует пользователь.

Функции:

* регистрация и авторизация
* просмотр коллекций
* добавление и редактирование предметов
* просмотр аналитики
* управление профилем

Отправляет HTTP-запросы к Backend API и отображает полученные данные.

---

### Backend (REST API)

Серверная часть приложения, реализующая бизнес-логику.

Основные задачи:

* обработка запросов от клиента
* управление данными
* авторизация и аутентификация (JWT)
* обработка логики коллекций и предметов

Модули:

* **Auth Service** — регистрация, логин, JWT
* **User/Profile Service** — управление профилем
* **Collections Service** — работа с коллекциями
* **Items Service** — управление предметами
* **Photos Service** — загрузка и хранение изображений
* **Favorites Service** — избранные предметы
* **Notifications Service** — уведомления пользователей
* **Analytics Service** — расчёт статистики

---

### PostgreSQL Database

Система хранения данных.

Хранит:

* пользователей
* коллекции
* предметы
* фотографии
* категории
* избранное
* уведомления

---

## Связи компонентов

* **User ↔ Frontend**

  * пользователь взаимодействует с приложением через интерфейс, который реализован в Backend

* **Frontend ↔ Backend**

  * взаимодействие через HTTP (REST API)
  * передача данных в формате JSON

* **Backend ↔ Database**

  * взаимодействие через SQL-запросы

* **Авторизация**

  * используется JWT (JSON Web Token)
  * токен передаётся в заголовке Authorization
